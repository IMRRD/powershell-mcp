# Disabled recurring import installation contract

These two units are **templates only**, not installed or enabled. Install them under `/etc/systemd/system/` only after the collector forced-command account, importer role, TLS route, and source identity are commissioned and reviewed. The timer's `[Install]` section makes an explicit later `systemctl enable --now analytics-recurring.timer` possible; nothing here enables it.

The caller is a dedicated `analytics-import` identity on the PostgreSQL host, **outside** `telemetry_storage_postgres`. Install reviewed Python files at `/opt/analytics-reviewed/operations/{recurring_import,collector_segment,incremental_transfer}.py` and `/opt/analytics-reviewed/import_jsonl.py`; pin their exact SHA-256 values in root-owned, mode 0600 `/etc/analytics-recurring/recurrence.conf`:

The unit pins the already-provisioned `/opt/analytics-reviewed/venv/bin/python` (observed psycopg 3.3.6 on the PostgreSQL host); `/usr/bin/python3` lacks psycopg. The recurring caller launches the importer with `sys.executable`, so the pin covers both processes. Before installing, verify the venv and psycopg as the intended service identity; do not silently fall back to system Python. This does not establish that the `analytics-import` account or its permissions have been commissioned.

```ini
COLLECTOR_SSH_HOST=collector-readonly@192.168.100.38
COLLECTOR_SEGMENT_SHA256=<reviewed collector_segment.py sha256>
INCREMENTAL_TRANSFER_SHA256=<reviewed incremental_transfer.py sha256>
IMPORTER_SHA256=<reviewed import_jsonl.py sha256>
```

The source `/opt/analytics-private-data/telemetry.jsonl` must retain its **original path and inode**; do not replace, truncate, or recreate it. Preserve the existing PostgreSQL checkpoint (initially 7201189 bytes, 27266 events; recheck live before installation). The owner requires write only to this protected source directory (including lock, identity, atomic receipt, and temporary chunks), and read to the installed code, classification JSON, dedicated SSH private key, pinned known_hosts, and `/etc/analytics-recurring/restricted-dsn`. Set ownership and modes independently; no DSN in command arguments, unit environment or logs. The DSN file contains the restricted importer login with `sslmode=verify-full`, `sslrootcert` pointing to the protected CA and a hostname matching the certificate SAN. Configure `hostaddr` to the address reachable **from this service's actual host network namespace**, port 55432 for the published endpoint if that route is admitted. A host-network retest with `host=docker-xrv3 hostaddr=192.168.100.81 port=55432` reached PostgreSQL but was rejected by `pg_hba.conf` for observed source `172.18.0.1`, `hermes_analytics_importer`, and `hermes_mcp_analytics_private` with SSL. This is not restricted-login proof. Any exception requires separate review of an exact database/role/source hostssl rule, not broad admission; retest the restricted login before activation. The previously proven `host=docker-xrv3 hostaddr=127.0.0.1 port=5432` works only inside the container namespace; it is not evidence for this host unit. Verify restricted-role TLS authentication and SELECT/INSERT permissions from the installed service identity before enabling; never swap to `sslmode=require` or an admin role to make it pass. If the host route is unavailable, do not activate this unit; explicitly choose and test an approved namespace-aware caller instead.

The collector account must be forced to the fixed reviewed `forced_segment.py` wrapper with `ANALYTICS_COLLECTOR_SOURCE` set on the collector, strict host-key checking, and no shell or forwarding grant. The wrapper must expose the same reviewed collector segment bytes pinned in the service. Recheck collector source prefix and inode against the source copy and protected identity state before the first run. This service uses its own nonblocking lock and receipt at stable paths; a failure preserves the prior `last_success` but changes `status` to `failed` and records a failure class. Monitor `last_attempt`, `last_success`, and `status` together; a timer tick or service exit without a fresh success receipt is not freshness. Incomplete trailing records and overlimit records fail rather than presenting false EOF. No native PostgreSQL-to-collector SSH authorization or restricted-role published-route proof is claimed by these templates.

Validate unit syntax with `systemd-analyze verify` on a compatible Linux system, inspect the installed `ExecStart` and resolved environment, execute an isolated fixture manually, then obtain explicit activation approval. Never run this template against the production source as a rehearsal.
