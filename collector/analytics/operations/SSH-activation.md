# Private activation over SSH command transport (not approved for production activation)

The controller CLI accepts `--ssh-pg-host`, `--ssh-grafana-host`, and `--ssh-identity-file` together. It keeps the receipt and pending/owned decisions on the controller. It sends only fixed resource operations and reviewed desired values through bounded SSH stdin; no SQL, URL, command, or secret is accepted in a request. Do not use these flags for production until the host-local prerequisites and change approval have been reviewed.

Each target requires Python, a reviewed copy of `collector/analytics/operations/activate_private.py` and the pinned analytics SQL/dashboard files at the expected relative paths, and `activate_private` importable by the target's Python process. Set `ANALYTICS_HELPER_BACKEND=pg` on the PostgreSQL host or `ANALYTICS_HELPER_BACKEND=grafana` on the Grafana host and `ANALYTICS_HELPER_CONFIG` to a private, target-local JSON configuration file. The PostgreSQL target needs `psycopg`, a local admin DSN file with permission to create/drop the dedicated database and roles, the two role-secret files, CA file and database host. The Grafana target needs the loopback Grafana URL, protected admin token file, dashboard-role secret file, CA file, database host, approved admin, and (for the exact Grafana 13.1.1 unsupported-org-delete classification) the local Grafana error log. The role password must be provisioned consistently on the two targets out of band; it is never sent from the controller. The helper's existing read-only PostgreSQL probe uses `ANALYTICS_LOCAL_PG_DSN`, independently of activation.

The isolated harness substitutes two separate target-local helper processes for SSH while exercising the actual controller CLI, PostgreSQL 17.11 and Grafana 13.1.1. It is not proof that production admin DSN/HBA, helper files, local credentials, or Grafana permissions have been provisioned. A timeout or malformed/missing result remains an unknown outcome with a pending receipt; reconcile by readback before any retry. The isolated harness's disposable-container provenance is required for database deletion; ordinary rollback retains the database pending a retention decision.
