# Recurring private analytics import — review gate

**Not installed or scheduled.** Production source, checkpoint, and database remain unchanged. Disabled, installable systemd templates and protected configuration/namespace contract are in `systemd/README.md`. The intended single owner is the PostgreSQL host (192.168.100.81), not a Hermes/LLM cron job. Direct TCP/22 from the controller to collector 192.168.100.38 and PG 192.168.100.81 was observed; paperclip-srv1 also reached both ports over an established WinRM session. TCP reachability does not establish SSH authorization or PostgreSQL privileges. No credential or production task was created by this PR.

## Constrained transport requested for review

On the collector, install reviewed `collector_segment.py` and `forced_segment.py` under a root-owned non-writable directory. Configure `ANALYTICS_COLLECTOR_SOURCE` to the exact collector JSONL path in a root-owned fixed wrapper, not a client-supplied path. Create a dedicated public-key-only SSH account or authorized-key entry with a **single fixed forced command** invoking that wrapper. Set `restrict,no-pty,no-agent-forwarding,no-port-forwarding,no-X11-forwarding` and `from="192.168.100.81"` if the observed source IP matches at the collector. Pin the collector host key in the PG host's protected known_hosts. Generate the private key on the PG host; do not move an existing general-purpose private key or grant a shell. Record and review exact public key, wrapper bytes/hash, authorized_keys line and source address before enabling. SSH_ORIGINAL_COMMAND is ignored by the endpoint. This is a proposal, **not an activated grant**.

A dedicated PG identity must have read/write access only to its private source copy, identity state, lock and receipt, read access to classification/DSN/key/known_hosts, and DB privileges limited to the reviewed importer schema. Ensure the source copy begins as the original checkpointed file **at its existing path and inode**; never replace, truncate or rebuild it. The coordinator appends only verified complete-line segments to that file, then runs the reviewed importer. Check the installed `collector_segment.py`, `incremental_transfer.py`, and `import_jsonl.py` SHA-256 against explicit approved command-line pins. Run with a protected service configuration (no DSN in argv). The receipt records first/last attempt, last success and a failure class; failed or interrupted attempts are not labeled success. `flock` prevents overlapping runs; segment budget is eight 4-MiB segments per attempt. A transport failure must exit nonzero and preserve the last-success timestamp. Importer DB transactions remain authoritative for checkpoint and row insertion. A restart may replay a verified suffix without duplication.

Before enabling a systemd timer, review the installed paths, hashes, source inode and PostgreSQL checkpoint, classify both identity and database permissions, run two isolated cycles and an on-host manual dry run against a **separate isolated fixture**, then authorize a finite timer and observe genuine runs. Do not sum legacy and v2 telemetry as independent events. No timer unit is shipped enabled and no production grant is installed. Existing analytics backup is not a substitute for recurrence.

Fixture test: `python -m unittest discover -s collector/analytics/operations -p 'test_recurring_import.py' -v`. It runs real segment extraction, verified append, coordinator, receipt and a subprocess importer stub on isolated files; it does not prove production SSH or PostgreSQL import.
