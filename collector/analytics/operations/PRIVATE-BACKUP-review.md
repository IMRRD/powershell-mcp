# Private analytics backup candidate — not installed or enabled

This service is **distinct from** `telemetry-postgres-backup.timer`, which protects another database. The production private analytics import and its source inode/checkpoint are untouched. Do not enable this timer before review and a manual end-to-end acceptance run. No private backup SSH grant or restricted dump role is assumed to exist.

The service runs on the PostgreSQL host as a dedicated `analytics-backup` identity, with a root-owned 0600 environment file `/etc/analytics-private-backup/backup.conf` containing `PRIVATE_SCHEMA_SHA256`, `PRIVATE_ROLES_SHA256`, `PGHOST`, `PGHOSTADDR`, `PGPORT`, `PGUSER`, `PGSSLMODE=verify-full`, `PGSSLROOTCERT`, `PGPASSFILE`. `PGPASSFILE` must be mode 0600 readable only to the caller; the environment file and host key/key material likewise must not be world-readable. Grant only CONNECT and enough SELECT to dump the private schema (including sequences), with TLS and an exact hostssl source; verify PostgreSQL 17 dumping with the installed pg_dump client. Do not reuse a broad admin key, open HBA/listener rules, or expose credentials in argv. The off-host SFTP identity must be directory-restricted and write/read/rename-only within its private-analytics destination; pin its host key. The service unit uses `/opt/analytics-reviewed/venv/bin/python` and ships **disabled**. Install only after verifying service identity, file ownership, DB authentication, SFTP confinement and unit syntax on the target; the current controller's proven SSH/SFTP path is evidence of reachability, not authorization for this new identity.

The custom-format `pg_dump` is a transaction-consistent full schema+data archive (`--no-owner --no-acl`), including checkpoint state. The exact reviewed `schema.sql` and `roles.sql` SHA-256 values are pinned for restore provenance. Restore to a **new disposable database** with pre-created narrowly scoped roles, `pg_restore --exit-on-error --no-owner --no-acl --dbname=<disposable> <archive>`, then apply pinned `roles.sql` as owner; verify event and checkpoint counts, prefix hash, dashboard aggregate access and raw-table denial. Never replay into production. The archive itself carries its schema; do not run schema.sql before restoring a full dump. Record database/client version, role provisioning, pinned hashes, actual restored results and exact dump hash in the review receipt.

The wrapper holds a nonblocking lock, checks local free space, writes `unknown` before work and `failed` on caught errors, and only writes `success` after SFTP staged upload, download/hash verification, remote rename to a unique immutable name and published download/hash verification. The 900-second monotonic coordinator deadline spans source checks, dump, four SFTP commands, readback hashing and success publication; each subprocess gets at most its own timeout or the remaining budget, whichever is smaller. The 20-minute systemd limit leaves 300 seconds for receipt/temporary-file cleanup (the contract requires at least 120 seconds). Python subprocess timeouts kill and reap direct children. Hash checks occur per chunk, not as a hard interrupt of a blocked filesystem call; cleanup and fsync can also block, so this is not an unconditional wall-clock guarantee. Local receipt replacement fsyncs the file and, on POSIX, the parent directory; Windows fixture tests cannot establish POSIX directory durability. A directory-sync failure after replace means visible receipt bytes may be uncertain across a crash and the caller fails closed rather than reporting success. SFTP rename and readback do **not** establish remote filesystem crash durability or server fsync. It never deletes old archives or history. On process termination, `unknown` persists; on failure, the last previously published archive survives, but the latest attempt receipt does **not** assert current freshness. Monitor receipt age/status and off-host available capacity; a failed/no receipt is not protection. Failed `.part` artifacts require manual inspection; no age-based cleanup is implemented. Local temporary dump is removed on exit; for abrupt host failure, manually inspect protected `.attempt-*` staging before any retry. The minimum free-space gate (100 MiB default) is only a floor, not a guarantee the dump fits: capacity alerting and an operator-managed archive plan are prerequisites for indefinite permanent retention.

Run fixture tests with `python -m unittest discover -s collector/analytics/operations -p test_private_backup.py -v`, and CLI help with `python collector/analytics/operations/private_backup.py --help`. Before installation run `systemd-analyze verify` on both units and a manual command under the proposed identity against disposable fixture credentials/off-host folder; read back the receipt, remote hash, and perform the restore above. Only after independent approval install files and then explicitly enable the timer. No timer activation is part of this candidate.
