# Private adoption report (offline)

Issue 63 adds optional random user pseudonym coverage, explicitly labelled
`externalSelfDeclared` and `cohortConflict` groups, and default whole-report
suppression for cells below 10 and derivable complements. A suppressed result has
`withheld: true` and no numeric groups; this is not zero activity. There is no
offline small-count override. See [the privacy/enrollment/migration contract](analytics/PRIVACY-ADOPTION.md).
Internal in-memory aggregation tests inspect fixture counts separately from the CLI.
The report consumes receipt-time-bounded enrollment entries as well as the legacy
explicit classification arrays; keep exact protected registry snapshots with reports.

For a maintainer with an **authorized local export** of collector JSONL only. This script opens local files; it has no network client, public route, deployment step, or connection to the production collector. Do not commit raw exports, classification files, or report output. Keep the private classification file outside the repository, restricted to the operator.

```
node collector/report.js --file /path/to/authorized-export.jsonl --classification /path/to/private-classification.json --from 2026-10-01T00:00:00.000Z --to 2026-10-08T00:00:00.000Z
```

The v2 `tool_metrics` event adds fixed per-tool outcome (`success`, `nonzero`, `error`, `timeout`, `cancelled`, `unknown`), duration (`lt100`, `lt1000`, `lt10000`, `gte10000` milliseconds) and feature (`execution`, `inspection`, `remote`, `transfer`, `lifecycle`, `logs`) count maps. All 20 registered MCP tools are instrumented once at the registration boundary. The handler's structured termination status determines process outcomes; an accepted RPC to poll a running job is not evidence that the job completed. No arguments, output, error text, target, path, account, host or caller-derived labels are recorded. `toolMetrics` in each report group aggregates these dimensions independently from legacy `toolCounts`; do not add them together. Existing startup and v1/legacy `tool_counts` records remain accepted. Collector v2 support must be deployed before v2-producing clients; no production rollout is implied by source tests.

Classification JSON: `{"internalHostIds":["..."],"testHostIds":["..."]}`. Supply explicitly known internal/test host IDs; unclassified records stay `unknownOrigin` (never "external users"). An empty list is allowed; no automatic inference from a host ID or IP is made. The output includes no host IDs or IPs. The half-open UTC window uses the event `ts`, not collection arrival time; counts may arrive late. `observedInstallations` means distinct host IDs with either accepted event in the window, `activeInstallations` distinct IDs with a `tool_counts` or `tool_metrics` event, and `startupOnlyInstallations` observed IDs without such an event. Versions and OS count one per observed ID using its earliest event in the window; version output preserves only canonical numeric `major.minor.patch` triples with each component 0–9999 (no leading zeros), and puts all other labels—including prereleases, build metadata, malformed values and untrusted text—into `other`. This bucket is not a raw label and cannot be interpreted as a specific version. OS and tool count keys are fixed allowlists; unexpected keys fail closed without echoing input. Tool counts sum delivered records, not deduplicated calls. These are observed installation proxies, **not people, users, downloads, or a census**. Opt-out, offline clients, failed delivery and startup-only sessions are not observable usage. Fire-and-forget sends and process-exit flushes are best-effort; an exit hook does not guarantee delivery. The script rejects invalid records rather than publishing a partial report and bounds input to 16 MiB / 100,000 lines; split larger exports into separately reviewed windows, without adding segment totals as distinct installations.

Collector implementation (`server.js`) accepts legacy startup/tool-count and versioned v2 tool-metric allowlists with a 16 KiB body cap, appending accepted payloads and `_receivedAt` but no new peer IP. Previously stored JSONL may contain `_ip`; do not delete or expose historical records. Its optional `TELEMETRY_TOKEN` guards POST only when configured; `/health` is public and there is no report/authentication endpoint or built-in raw-record access control/retention schedule here. The report never reads `_ip` into its output. Deployment access controls and actual retention cannot be inferred from this repository. Do not expose raw JSONL; limit local access and manage retention through the authorized operator's deployment process. The client sends stable local host ID, event, version, OS, UTC timestamp, and, for flushes, named tool counts; no commands, arguments, outputs or paths. `POWERSHELL_MCP_NO_TELEMETRY=1` disables ID creation, counting, startup and flush. Tests set an explicit loopback fixture endpoint; never point fixture traffic at production.

Run isolated validation: `node scripts/check-collector-tests.mjs` (CI and the reusable publish gate require nonzero discovered tests, all passing). This does not need collector credentials or production access.

A dated aggregate-only public-channel snapshot is checked in as [`snapshot-2026-10-06_2026-10-19.json`](snapshot-2026-10-06_2026-10-19.json). It was retrieved using the npm downloads API for both scoped and legacy names and authorized read-only GitHub traffic API, covering the inclusive UTC days October 6–19, 2026. Reproduce a new, complete 14-day window with `node collector/snapshot.mjs YYYY-MM-DD YYYY-MM-DD path/to/new-snapshot.json`; `gh` must have read access to repository traffic. This command does **not** access the collector; missing/partial API responses fail without creating a report. npm downloads and GitHub clones/views are events, never unique installations or people, and may include internal/test traffic. GitHub's reported unique estimates must not be added across days or interpreted as users. Collector installation aggregates remain unavailable absent an authorized local export; do not substitute these public-channel events.

For tool counts, the available payload has no event ID or monotonic sequence. Distinct host IDs are deduplicated for installation metrics; **every delivered `tool_counts` record is summed**, including byte-identical repeats. Deduplicating equal records could erase independent tool uses, while summing replays can inflate counts; the report therefore does not assert exactly-once calls. The repeat-delivery fixture locks down this explicit limitation.
